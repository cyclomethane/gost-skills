# gost-skills — скилл ИИ-агента для оформления и приёмки документов по ГОСТ

Один скилл для ИИ-агентов (ZCode, Claude Code и любые ассистенты, читающие
`.agents/skills/`): собери документ по стандарту или пришли готовый — скилл
вернёт отчёт, в котором каждое замечание имеет ссылку на пункт ГОСТ или
методички.

[`skills/gost`](skills/gost/) покрывает: диссертации и авторефераты (ГОСТ Р
7.0.11-2011, структура, титульный лист, оглавление, введение, формулы,
приложения + приёмочный скрипт `gost_acceptance.py`), ВКР, дипломы, курсовые и
отчёты по практике, отчёты о НИР (ГОСТ 7.32-2017), журнальные статьи (ГОСТ Р
7.0.7-2021), рефераты и аннотации (ГОСТ Р 7.0.99-2018),
организационно-распорядительные документы (ГОСТ Р 7.0.97-2025), текстовые
документы ЕСКД (ГОСТ Р 2.105-2019), библиографию (ГОСТ Р 7.0.5-2008,
7.0.100-2018, 7.0.108-2022), единицы величин (ГОСТ 8.417-2024), презентацию и
доклад на защите.

Общие требования не размазаны по модулям, а собраны в двух файлах:
[`layout-core.md`](skills/gost/references/layout-core.md) — вся визуальная
вёрстка в трёх профилях (А — ГОСТ Р 7.0.11, Б — ГОСТ 7.32, В — ГОСТ Р 2.105) с
готовыми значениями DOCX, и
[`mandatory-core.md`](skills/gost/references/mandatory-core.md) — матрица
обязательных структурных элементов, состав титульного листа, элементы введения
и нормы объёма. Модули типов документов содержат только свои отличия.

## Установка

Скопируй папку скилла в каталог скиллов агента:

```bash
# для одного проекта
git clone https://github.com/cyclomethane/gost-skills.git
mkdir -p .agents/skills
cp -r gost-skills/skills/gost .agents/skills/gost

# или глобально, для всех проектов
cp -r gost-skills/skills/gost ~/.agents/skills/gost
```

Каталоги обнаружения по приоритету: `<проект>/.agents/skills/`, затем
`~/.agents/skills/`.

## Как это работает

1. Ты называешь документ или даёшь файл — скилл определяет тип, выбирает
   профиль вёрстки и подключает модуль: для ВКР это поля 30/15/20/20 мм и номер
   страницы в центре нижней части листа (ГОСТ 7.32-2017, п. 6.1 и 6.3), для
   диссертации 25/10/20/20 и номер посередине верхнего поля, и так далее.
   Сначала проверяются обязательные элементы: чего не хватает в структуре,
   какого элемента нет во введении, укладывается ли объём в норму.
2. Механическая проверка читает `document.xml` распакованного DOCX: поля и
   кегль в твипах и полупунктах, межстрочный интервал, колонтитулы, заголовки
   без темевой подмены шрифтов, автособираемое оглавление, подписи таблиц и
   рисунков по ГОСТ 2.105, формулы как объекты OMML, метаданные без следов
   автоматизации.
3. Содержательная проверка сверяет структуру с модулем: титульный лист,
   введение, сокращения, список литературы, приложения.
4. На выходе — отчёт со статусами PASS / FAIL / N/A / NEEDS_SOURCE_CHECK и
   трассировкой к пунктам стандарта. Примеры запросов: «проверь эту ВКР по
   ГОСТ», «собери аннотацию к статье по 7.0.7», «проверь список литературы по
   7.0.100».

Скилл включает приёмочный скрипт
[`scripts/gost_acceptance.py`](skills/gost/scripts/gost_acceptance.py) — больше
50 машинных проверок, от обязательных структурных элементов и объёма до полей,
кегля, подписей и геометрии формульных строк. Отчёт разложен по тем же
разделам, что и отчёт скилла, каждый пункт помечен GATE, INFO или «отклонение».

```bash
python skills/gost/scripts/gost_acceptance.py Работа.docx     --profile B --type vkr --min-pages 60 --max-pages 90 --min-sources 40
```

`--profile A|B` выбирает набор значений вёрстки, `--type
dissertation|vkr|nir|generic` — набор обязательных элементов, границы объёма и
числа источников берутся из локальной методички. Скрипту нужны Python 3.10+ и
`lxml`; файл он только читает.

## Приоритет требований и границы

1. Требования вуза, кафедры, диссертационного совета или редакции.
2. Действующие национальные стандарты в пределах области применения.
3. Модули как нормализованная рабочая интерпретация стандартов.

Расхождение локальной методички со стандартом фиксируется в отчёте с обеими
ссылками. Модули не заменяют тексты стандартов: официальные карточки на
protect.gost.ru указаны в шапках модулей, действие редакций сверяется по
указателю «Национальные стандарты» на текущий год; непроверенное требование
помечается NEEDS_SOURCE_CHECK. Любая математика ведётся объектами OMML, не
картинками.

## Статус

Версия модулей — 2026-09-16. Курсовая, отчёт по практике и инженерная
пояснительная записка собираются из модуля ВКР и профиля вёрстки; типы без
модуля (тезисы конференции, монография, документы совета) требований не
выдумывают — для них нужен источник: методичка или стандарт.
