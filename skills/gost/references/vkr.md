# ВКР: нормативный статус, структура, аудит, защита

## 1. Нормативный статус: единого ГОСТ нет

Действующего национального стандарта «Выпускная квалификационная работа.
Структура и правила оформления» не существует. Приказ Минобрнауки России от
29.06.2015 № 636 (ред. от 04.02.2025) закрепляет: ВКР демонстрирует уровень
подготовленности выпускника к самостоятельной профессиональной деятельности; вид
ВКР, требования к ней, порядок выполнения и критерии оценки устанавливает
образовательная организация; организация утверждает перечень тем, студент может
предложить свою с обоснованием; назначается руководитель, он представляет отзыв;
ВКР магистратуры и специалитета подлежат рецензированию; обучающегося знакомят с
отзывом и рецензией до защиты в установленные сроки; текст размещают в ЭБС
организации и проверяют на объём заимствований, кроме установленных законом
исключений.

Иерархия требований для конкретной ВКР:

1. ФГОС или собственный образовательный стандарт вуза по программе.
2. Локальный порядок ГИА вуза.
3. Положение о ВКР вуза, института, факультета.
4. Методические рекомендации кафедры или образовательной программы.
5. Утверждённые шаблоны титульного листа, задания, отзыва, рецензии, реферата,
   презентации.
6. ГОСТы, на которые ссылаются локальные документы.
7. Настоящий модуль как безопасный профиль по умолчанию.

При расхождении конкретного параметра берётся значение с наиболее высокого
уровня. Этот модуль применяется, когда методичка отсутствует, неполна или
требует содержательного дополнения.

## 2. Какие ГОСТы реально применяются

| Стандарт | Роль для ВКР |
| --- | --- |
| ГОСТ 7.32-2017 | основной профиль оформления текста — профиль Б, `nir-report-7.32.md` |
| ГОСТ Р 7.0.11-2011 | структурная модель научного представления работы: общая характеристика → основное содержание → заключение → публикации, `dissertation.md` |
| ГОСТ Р 7.0.99-2018 | реферат и аннотация ВКР, `abstract-referat-7.0.99.md` |
| ГОСТ Р 7.0.5-2008 | библиографические ссылки, `references-7.0.5.md` |
| ГОСТ Р 7.0.100-2018 | библиографические записи списка, `bibliography-records-7.0.100.md` |
| ГОСТ Р 7.0.108-2022 | ссылки на сетевые документы, `web-references-7.0.108.md` |
| ГОСТ Р 2.105-2019 | текстовая конструкторская документация, пояснительная записка, `text-documents-2.105.md` |
| ГОСТ 8.417-2024 | единицы величин, `units-8.417.md` |
| ЕСКД, ЕСПД, ЕСТД, СПДС, отраслевые нормы | применяются только к тем элементам работы, которые относятся к соответствующему виду документации |

Модель ГОСТ Р 7.0.11 особенно полезна для исследовательской ВКР бакалавра,
дипломной работы специалиста, магистерской диссертации и работ с собственным
экспериментом, моделью, алгоритмом или программной реализацией.

## 3. Тип ВКР определяется до начала работы

| Тип | Основной результат | Композиция основной части |
| --- | --- | --- |
| Исследовательская | научный вывод, модель, метод, алгоритм, экспериментальная закономерность, сравнительный результат | обзор состояния вопроса → постановка задачи → методология → собственный метод → эксперимент → анализ результатов |
| Проектная | система, устройство, архитектура, технологический процесс, проект, проектная документация | анализ задачи и аналогов → требования → проектные решения → расчёты и моделирование → реализация → испытания на соответствие требованиям |
| Программная | программная система, библиотека, сервис, алгоритм, информационная система | постановка задачи → анализ решений → требования → архитектура → алгоритмы → реализация → тестирование → экспериментальная оценка → ограничения |
| Аналитическая | аналитическая модель, оценка, классификация, интерпретация корпуса источников, рекомендации | проблема → состояние исследований → метод анализа → материал → результаты анализа → выводы и рекомендации |

Число глав стандартом не задано; типично 2–3 содержательные главы, структура
выбирается по логике исследования и локальным требованиям. Научная новизна
обязательна для магистерской и исследовательской работы; для части бакалаврских
программ достаточно самостоятельного исследовательского или проектного
результата. Положения, выносимые на защиту, для ВКР обязательны только при
прямом требовании локального документа.

Допустимые типы вклада, которые можно называть элементами новизны: новая
постановка прикладной задачи; адаптация известного метода к новому классу
данных; модификация алгоритма; новая процедура обработки данных; новый
программный модуль; новая схема интеграции компонентов; новая экспериментальная
проверка; новая сравнительная оценка; выявленная закономерность; новые
количественные результаты; систематизация, дающая обоснованную практическую
методику; проектное решение под заданные ограничения. Уровень формулировки
новизны должен совпадать с уровнем доказательства в основной части.

## 4. Структура: что добавляется к матрице `mandatory-core.md`

Полный профиль элементов: титульный лист; задание на ВКР; календарный план;
реферат или аннотация на русском; abstract при требовании; перечень сокращений и
обозначений; содержание; введение; основная часть; заключение; список
использованных источников; список публикаций по теме; приложения; графические
листы, спецификации, программная документация для соответствующих направлений.

**Задание на ВКР.** ФИО студента; группа; тема; документ об утверждении темы;
срок представления; исходные данные; перечень основных вопросов и разделов;
перечень графического материала; перечень программных результатов; консультанты;
дата выдачи; подписи руководителя и студента. Задание сверяется с фактическим
содержанием готовой работы: финальная версия должна отвечать поставленным в
задании задачам — расхождение задания и текста идёт в критические нарушения.

**Реферат ВКР** по ГОСТ Р 7.0.99-2018: сведения об объёме работы; количество
рисунков, таблиц, источников, приложений; ключевые слова; объект; предмет; цель;
методы; результаты; практическое применение; вывод о полученном результате. Для
технической ВКР добавляют программные средства, оборудование, среду
вычислительного эксперимента и основные технические характеристики результата.
Ключевые слова отражают предмет работы, совпадают с терминологией текста,
позволяют найти работу по тематическому запросу и включают название ключевого
метода или объекта.

**Перечень сокращений и обозначений** создают, когда сокращений много, есть
специальные математические обозначения, используются отраслевые аббревиатуры или
читателю нужен единый справочный блок. Термин используется в тексте в одной
форме; первое употребление специального сокращения раскрывают; математические
символы совпадают с формулами.

**Содержание** включает введение, все главы и подразделы установленного уровня,
заключение, список источников, приложения и все фактически присутствующие
структурные элементы. Перед сдачей обновляются все поля документа и
перепроверяются номера страниц.

## 5. Введение: что должен содержать каждый элемент

Состав и обязательность — `mandatory-core.md`, раздел 3. Требования к содержанию:

- **актуальность** — какая проблема есть, почему решать нужно сейчас, какой
  дефицит знания, метода, системы или практики остаётся, для кого важен
  результат; опора на факты, публикации, нормативные требования, статистику или
  конкретный технологический дефицит;
- **степень разработанности** — существующие подходы, ключевые авторы и системы,
  уже полученные результаты, открытая часть проблемы; обзор заканчивается
  исследовательским разрывом, который закрывает ВКР;
- **проблема** — противоречие, дефицит метода, недостаток данных, ограничение
  технологии, отсутствие проверенного решения или необходимость выбора между
  альтернативами;
- **объект** — более широкая система, процесс, класс задач, предметная область;
  **предмет** — конкретное свойство, отношение, метод, механизм, часть объекта,
  исследуемая непосредственно;
- **цель** — один конечный результат; глаголы: разработать, обосновать,
  исследовать, определить, построить, оценить, выявить, усовершенствовать,
  спроектировать;
- **задачи** — каждая ведёт к цели, имеет результат, раскрыта в тексте и
  получает ответ в заключении; число крупных задач близко к числу смысловых
  этапов исследования;
- **методология и методы** — предметно: методы анализа данных, математические
  методы, экспериментальный дизайн, моделирование, статистическая проверка,
  программные технологии, методы проектирования, сравнительный анализ; для
  нового или модифицированного метода — его роль;
- **информационная и экспериментальная база** — наборы и источники данных,
  выборки, программное обеспечение, оборудование, базы документов, нормативные
  источники, экспериментальные стенды;
- **новизна** — каждая формулировка имеет доказательную опору в основной части;
- **теоретическая значимость** — вклад в модель, метод, классификацию, описание
  закономерностей, постановку задачи, формализацию;
- **практическая значимость** — где применяется результат, что улучшает, какие
  ограничения снимает, какой измеримый эффект даёт, какие программные или
  методические материалы созданы;
- **достоверность** — корректная постановка эксперимента, повторяемость,
  контрольные сценарии, сравнение с известными методами, статистическая
  обработка, тестирование программы, совпадение аналитического и вычислительного
  результата, открытые исходные данные, сохранённые артефакты вычислений;
- **апробация** — конференции, публикации, семинары, внедрение, использование в
  проекте, акт апробации;
- **результаты к защите** — 2–5 проверяемых результатов, каждый конкретный,
  авторский, доказанный, связанный с целью и подтверждаемый таблицей, рисунком,
  формулой, программой или экспериментом;
- **личный вклад** — какие алгоритмы, эксперименты, модули, данные и выводы
  принадлежат автору; обязателен для работ в лаборатории, проектной команде или
  на общем программном комплексе;
- **структура работы** — число глав, объём, количество рисунков, таблиц,
  источников, приложений.

## 6. Основная часть и заключение

Цепочка основной части: проблема → известные решения → постановка задачи →
выбранный метод → реализация → проверка → результат → интерпретация. Каждый
крупный раздел продвигает работу к цели.

**Глава обзора:** научные подходы, современные аналоги, классификация методов,
сравнительный анализ, ограничения аналогов, вывод о месте собственной работы;
заканчивается постановкой исследовательской задачи. **Глава методологии и
разработки:** для исследования — математическая постановка, определения,
допущения, алгоритм, критерий остановки, параметры, вычислительная схема; для
проекта — требования, ограничения, архитектура, выбор технологий, проектные
решения, расчёты; для программной работы — архитектура программы, модели данных,
алгоритмы, интерфейсы компонентов, ключевые модули, программная среда,
воспроизводимость сборки и запуска. **Глава экспериментов:** цель эксперимента,
гипотеза, исходные данные, правила разбиения данных, методы сравнения,
параметры, метрики, вычислительная среда, число повторов, критерии успешности,
результаты, отрицательные результаты, ограничения. **Глава обсуждения:** что
показано, почему возник эффект, согласуется ли результат с известными
исследованиями, где он устойчив, где появляются ограничения, какие
альтернативные объяснения остаются, какой практический смысл имеет результат.

**Заключение:** кратко решённая проблема → последовательные ответы на задачи →
основные результаты → количественные значения ключевых результатов →
практический эффект → ограничения → перспективы. Каждый вывод имеет источник в
основном тексте. Новые методы, данные и результаты в заключении не появляются.

## 7. Программная и вычислительная ВКР

Комплект воспроизводимости: исходный код; инструкции запуска; версии языка и
библиотек; конфигурационные файлы; исходные данные или ссылки на них; правила
подготовки данных; параметры моделей; случайные seed при стохастическом
эксперименте; результаты прогонов; журналы выполнения; таблицы метрик;
изображения графиков; контрольные примеры.

В тексте должны быть понятны назначение программы, входные и выходные данные,
архитектура, ключевые алгоритмы, ограничения, порядок запуска, порядок
тестирования, подтверждение корректности. Полный код хранят в приложении или
репозитории, в основном тексте оставляют только листинги, нужные для понимания
метода. Тестирование показывают функциональными тестами, контрольными примерами,
обработкой граничных случаев, верификацией численных результатов, сравнением с
эталонным решением и повторяемостью ключевых экспериментов.

## 8. Библиография и качество источников

Каждая заимствованная идея, метод, формула, числовой факт, рисунок и
утверждение, требующее внешнего подтверждения, получает ссылку. Система ссылок —
установленная вузом: затекстовые в квадратных скобках, подстрочные или
внутритекстовые; для научно-технической ВКР чаще всего нумерованные затекстовые.
Один стиль на весь документ.

В список включают только реально использованные источники; для каждого
проверяют автора, название, сведения об издании, год, том и номер, страницы,
DOI, URL и дату обращения, если её требует тип ресурса и локальный стандарт.
Приоритет источников: нормативные документы; рецензируемые научные статьи;
монографии; официальная техническая документация; материалы конференций;
диссертации и авторефераты; репозитории данных; официальные сайты организаций.
Обзор современной технической темы содержит и работы последних лет, и
фундаментальные источники.

## 9. Приложения

В приложения выносят объёмные таблицы, вспомогательные расчёты, листинги, формы
документов, спецификации, схемы большого формата, дополнительные графики,
протоколы экспериментов, примеры входных и выходных данных, акты внедрения,
дополнительные результаты тестирования. На каждое приложение — содержательная
ссылка в основном тексте; обозначение и заголовок — по правилам локальной
методики. Остальное — `layout-core.md`, раздел 10.

## 10. Академическая добросовестность

Порядок ГИА предусматривает размещение текста в ЭБС организации и проверку
объёма заимствований с установленными исключениями. Соблюдай локальный регламент
проверки; ссылайся на все заимствованные положения; оформляй прямые цитаты по
правилам; сохраняй исходные данные и черновые артефакты собственного
исследования; отделяй собственный результат от результатов других авторов.
Политику вуза по генеративным моделям проверяй отдельно: в 2026 году часть
российских университетов включила соответствующие правила в регламенты
академической этики. Фиксируй собственный вклад, проверяй фактические
утверждения по первичным источникам, сохраняй вычислительные артефакты,
подтверждающие результаты.

## 11. Порядок выполнения работы

Изучить локальное положение и скачать шаблоны → согласовать тему →
сформулировать проблему, объект, предмет → сформулировать цель и разложить её на
задачи → согласовать структуру с руководителем → выполнить обзор литературы →
зафиксировать методологию → выполнить исследование, проект или разработку →
провести эксперимент или испытания → собрать доказательную базу → написать
основную часть → собрать введение по фактически выполненной работе → написать
заключение как ответы на задачи → оформить реферат → проверить ссылки и список
источников → проверить таблицы, рисунки, формулы → выполнить автоматическую
проверку структуры и оформления → передать версию руководителю → получить отзыв
и, если предусмотрена, рецензию → пройти проверку заимствований → загрузить текст
в установленную систему → подготовить доклад и презентацию → провести репетицию
защиты → подготовить ответы на замечания → зафиксировать финальную версию со
всеми приложениями.

Оформлять документ стилями Word нужно с первого дня: автоматические стили,
подписи, нумерация и собираемое содержание резко снижают число ошибок
нормоконтроля. Защиту готовят параллельно с финальной редакцией — формирование
доклада выявляет слабые места логики раньше сдачи.

## 12. Защита

Полный модуль — `defense-presentation.md`. Единой федеральной длительности
доклада нет: требования МГУ 2026 предусматривают 10–12 минут, отдельные
программы НИУ ВШЭ — до 15 минут; при отсутствии локального значения рабочий
ориентир 10 минут. Структура доклада: тема; проблема и актуальность; цель;
задачи; объект и предмет; метод; собственная разработка; эксперимент; 2–4
ключевых результата; практическая значимость; ограничения; итог. Основное время
отводится собственным результатам. Минимальный набор слайдов: титульный;
проблема; цель и задачи; схема метода или проекта; данные; ключевые результаты;
сравнение; практический результат; итоговые выводы. Готовь ответы о выборе
метода и аналогов, ограничениях, достоверности, статистике, происхождении данных,
личном вкладе, практической значимости, воспроизводимости и причинах
отрицательных результатов.

## 13. Критерии сильной работы

**Содержание:** ясная проблема; обоснованная актуальность; знание литературы;
самостоятельная постановка задачи; обоснованный метод; достаточный объём
собственной работы; корректный эксперимент; доказательные результаты;
обозначенные границы применимости; практический или научный вклад.
**Форма:** соответствие локальной методичке; полнота структуры; корректный
титульный лист; совпадение содержания и текста; поля, шрифт, интервалы,
абзацы, нумерация, заголовки, рисунки, таблицы, формулы, ссылки, список
источников, приложения. **Защита:** выпускник ясно объясняет проблему,
понимает собственный метод, знает литературу, аргументирует решения, корректно
интерпретирует результаты, отвечает предметно, объясняет ограничения и отделяет
свой вклад от внешних источников.

## 14. Частые ошибки

**Логика:** цель шире фактического результата; задачи не соответствуют главам;
объект и предмет перепутаны; обзор литературы существует отдельно от постановки
задачи; метод выбран без обоснования; сравниваются несопоставимые сценарии;
выводы выходят за пределы эксперимента; заявленная новизна не подтверждена;
практическая значимость без сценария применения; ограничения скрыты.

**Структура:** отсутствует обязательный элемент локальной методички; введение
обещает результаты, которые затем не подтверждаются; заключение пересказывает
главы; главы диспропорциональны; названия глав слишком общие; приложения не
связаны с текстом; содержание не обновлено.

**Оформление:** перечень — `layout-core.md`, раздел 14.

**Защита:** доклад пересказывает всю работу; собственный результат появляется
слишком поздно; на слайдах слишком много текста; нет количественных результатов;
нет слайда с итогом; автор не может объяснить выбор метода; автор не знает
ограничения; ответы на замечания рецензента не подготовлены.

## 15. Машинный чек-лист

**Источник требований:** определены вуз, институт, кафедра или программа;
найдены положение о ГИА, положение о ВКР, методические рекомендации, шаблоны
титульного листа, задания, отзыва и рецензии; установлены режим проверки
заимствований, сроки сдачи, длительность доклада.

**Структура и объём:** по матрице и нормам `mandatory-core.md`.

**Введение:** все элементы раздела 5 присутствуют или обоснованно не применяются.

**Логика.** Для каждой задачи: есть раздел, где она решается; есть результат;
есть доказательство или эксперимент; есть вывод; результат отражён в заключении.
Для каждой формулировки новизны: указан авторский элемент; есть конкретный
артефакт; есть доказательство; определены ограничения.

**Эксперимент:** описаны данные и их источник; описана предподготовка; разделение
выборок корректно; утечка данных исключена; метрики соответствуют задаче; есть
методы сравнения; условия сравнения сопоставимы; зафиксированы параметры, число
повторов и среда выполнения; результаты сохранены; описаны отрицательные
результаты и границы применимости.

**Программная реализация:** описаны архитектура, входы, выходы, ключевые
алгоритмы; есть инструкция запуска; зафиксированы версии зависимостей; есть
тесты или контрольные примеры; результаты воспроизводимы; листинги не
перегружают основную часть; полный код вынесен в приложение или репозиторий.

**Оформление:** по чек-листу `layout-core.md` в значениях профиля Б или
локального шаблона.

**Рисунки.** Для каждого: номер; название; ссылка в тексте; читаемое
изображение; подписанные оси; единицы; понятная легенда; источник для
заимствованного материала; объяснение результата в тексте.

**Таблицы.** Для каждой: номер; название; ссылка в тексте; понятные заголовки
столбцов; единицы; корректный перенос; согласованность значений с текстом; вывод
по таблице в тексте.

**Формулы.** Для каждой: все обозначения определены; индексы единообразны;
единицы согласованы; номер есть при наличии ссылки; ссылка корректна; формула
совпадает с программной реализацией, если реализована в коде.

**Литература:** все ссылки из текста имеют запись в списке; все записи реально
используются; оформление единообразно; проверены DOI, URL, авторы, годы; есть
фундаментальные источники, современные исследования и ближайшие аналоги;
источники соответствуют теме.

**Заключение:** каждая задача получила ответ; приведены главные и количественные
результаты; есть практический эффект, ограничения, перспективы; новых данных нет.

**Защита:** доклад укладывается в лимит; цель сформулирована за 1–2 предложения;
собственный результат появляется в первой половине доклада; ключевые результаты
представлены числами; слайды читаемы; таблицы сокращены до существенного; есть
финальные выводы; подготовлены ответы на замечания руководителя и рецензента, о
личном вкладе и об ограничениях.

## 16. Алгоритм аудита готовой ВКР

1. **Локальные правила.** Извлечь из методички или с сайта вуза: тип ВКР;
   обязательную структуру; объём; параметры страницы; правила ссылок; правила
   рисунков, таблиц, формул; требования к реферату; регламент заимствований;
   правила защиты.
2. **Карта требований.** Каждому требованию — статус: ОБЯЗАТЕЛЬНО (закреплено
   локальным актом или применимым стандартом); РЕКОМЕНДОВАНО (сводная
   академическая практика); НЕ ПРИМЕНИМО (элемент не предусмотрен для этого
   типа); ТРЕБУЕТ УТОЧНЕНИЯ (локальный документ не даёт информации).
3. **Обязательные элементы и объём** по `mandatory-core.md` — первым разделом
   отчёта.
4. **Научная логика** по цепочке: тема → проблема → цель → задачи → главы →
   метод → результаты → заключение. Каждый разрыв фиксируется отдельно.
5. **Доказательность.** Для каждого важного утверждения — источник: литература,
   формула, алгоритм, таблица, рисунок, эксперимент, программный артефакт.
6. **Оформление** по `layout-core.md` в порядке: параметры страницы → стили
   текста → заголовки → нумерация → содержание → рисунки → таблицы → формулы →
   ссылки → список литературы → приложения.

**Формат отчёта.** A. Критические нарушения — способные привести к возврату
нормоконтролем, недопуску или существенному снижению оценки; для каждого:
местоположение, правило, обнаруженное состояние, требуемое состояние, источник
требования, способ исправления. B. Содержательные проблемы — логика
исследования, соответствие цели и результатов, самостоятельность, методология,
доказательность, полнота эксперимента, выводы. C. Формальные нарушения — шрифт,
поля, интервалы, нумерация, подписи, библиография, приложения. D. Рекомендации
усиления — только изменения с заметным эффектом при разумной трудоёмкости.
E. Итоговый чек-лист, один статус на правило: `[x]` выполнено, `[ ]` требуется
исправление, `[?]` требуется локальное уточнение, `[–]` не применяется.

## 19. Решающее правило

Перед работой над конкретной ВКР загрузи в контекст локальное положение о ВКР,
методические рекомендации кафедры, шаблон титульного листа, шаблон задания,
критерии оценки, правила проверки заимствований и требования к защите. После
этого используй модуль для заполнения пробелов, проверки логики и расширенного
нормоконтроля. Профиль по умолчанию: структура по модели ГОСТ Р 7.0.11-2011 +
оформление по ГОСТ 7.32-2017 (профиль Б) + реферат по ГОСТ Р 7.0.99-2018 +
ссылки по ГОСТ Р 7.0.5-2008 + записи по ГОСТ Р 7.0.100-2018 + профильные
инженерные стандарты при наличии технической документации.
