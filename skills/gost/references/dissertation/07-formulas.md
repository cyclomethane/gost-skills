# Часть VII. Оформление формул: строки нумерации, OMML, реестр исходников

Свод практики поверх ГОСТ Р 7.0.11-2011: как верстается формула
с номером, чем закрывается каждый риск «съезжания» и где живут LaTeX-исходники.

## 1. Требования ГОСТ — исходный пункт 5.3.11

- в качестве символов применяют обозначения, установленные соответствующими
  национальными стандартами;
- пояснения символов приводят в тексте или непосредственно под формулой;
- формулы нумеруют арабскими цифрами сквозной нумерацией или в пределах
  главы/раздела;
- номер формулы заключают в круглые скобки;
- номер располагают справа на уровне формулы;
- формулы оформляют в соответствии с ГОСТ 2.105.

## 2. Правило скилла: вся математика — OMML

Правило строже ГОСТ и объявлено в `SKILL.md`: формула в DOCX — объект
Office Math. Выключная формула — `m:oMathPara`, строчная формула, символ в
тексте и каждая буква в пояснении «где» — `m:oMath`. Индексы — структуры
`m:sSub`/`m:sSup`/`m:sSubSup` (t с пониженной L), а не слипшийся текст «tL»,
не курсив и не надстрочный текстовый прогон. Растр, EMF и EQ-поля не проходят.
Формула, «сгоревшая» в рисунок подписи, требованию не отвечает.

## 3. Конструкция формульной строки

Формула с номером верстается таблицей-врезкой без рамки: одна строка,
две ячейки. Точные значения сборки:

| Элемент | Значение | Зачем |
| --- | --- | --- |
| `w:tblW` | dxa 9355 (полоса набора 165 мм = 210 − 30 − 15) | строка занимает всю полосу на любой длине формулы |
| `w:tblLayout` | fixed | без fixed Word подгоняет колонки под содержимое, и номер уходит от края |
| левая ячейка `w:tcW` | dxa 8505 (148,5 мм) | формула; абзац `jc=center`, отступ 0, интервал одинарный; формула — `m:oMathPara` с `m:jc=center` |
| правая ячейка `w:tcW` | dxa 850 (15 мм) | номер «(N.M)» кеглем 12 пт, абзац `jc=right` |
| `w:vAlign` обеих ячеек | center | у высокой формулы (cases, дроби) номер остаётся на уровне формулы, а не прилипает к верху строки |
| `w:trPr/w:cantSplit` | есть | строка не разрывается между страницами |
| `w:tblBorders` | все `none` | врезка невидима |

Двойное центрирование (абзац `jc=center` и `m:oMathPara/m:jc=center`)
согласовано и намеренно.

Порядок дочерних элементов `tblPr` и `tcPr` строгий по схеме: `tblW` — до
`jc`/`tblBorders`/`tblLayout`, `tcW` — до `tcMar`, `vAlign` — после `tcMar`.
Нарушенный порядок Word считает порчей файла. Вставляйте элементы через
`insert_element_before` со списком последователей, а не `append`.

## 4. Ловушки

- `tblLayout=autofit` и `tblW=auto`: колонки подгоняются под содержимое —
  положение номера зависит от длины формулы.
- Без `vAlign=center` номер высокой формулы прилипает к верхнему краю строки.
- Удаление частей `customXml/*` из пакета ломает открытие файла в Word
  («файл повреждён»; подтверждено бисекцией по операциям перепаковки).
  Миниатюра `docProps/thumbnail.jpeg` удаляется безопасно.
- Присвоение `description=""` в python-docx не чистит текст шаблона
  «generated by python-docx» — элемент `dc:description` удаляется перепаковкой.
- Табуляторы и плоские индексы — мусор копирования из исходника: табулятор
  нормализуется пробелом, плоский токен конвертируется через `inline.text`.
- `~$*.docx` — lock-файл Word: сборка при открытом в Word документе упадёт
  по правам; закройте документ перед пересборкой.

## 5. Реестр исходников FORMULA_SOURCES.json

Маршрут: LaTeX → MathML (`latex2mathml`) → OMML (`MML2OMML.XSL` из поставки
Microsoft Office). Новая запись проверяется конвертацией до попадания в
реестр; сборщик падает громко, если исходника нет (`omml_missing`).

| Секция | Ключ | Значение | Покрывает |
| --- | --- | --- | --- |
| `formulas` | «N.M» | `{latex}` | выключные формулы по номерам |
| `inline.raster` | имя файла в MEDIA | latex | обозначения, вставленные в исходник растрами |
| `inline.code` | текст код-вставки | latex или `null` | формулы в код-вставках; `null` = намеренный текст (статусы, платформы) |
| `inline.italic` | курсивный фрагмент | latex или `null` | одиночные буквы и символы |
| `inline.text` | плоский токен | latex | слипшиеся индексы исходника (tL → t_L); границы слова соблюдаются, внутри код-вставок и курсива замена не применяется |

## 6. Пояснения «где»

Каждый абзац, начинающийся с «где», обязан содержать хотя бы один объект
OMML — символ расшифровки. Формула без блока «где» с расшифровкой новых
символов — дефект содержательной проверки. Отсылки в тексте вида «по формуле
(3.4)» пояснениями не считаются и под гейт не подпадают.

## 7. Проверка

Механика (`scripts/gost_acceptance.py`): номера не повторяются, прижаты вправо,
левая ячейка непустая, нумерация без пропусков в пределах главы, OMML не
меньше нумерованных записей, формула не растром, формульная строка —
фиксированная полоса (fixed, ширина полосы набора) с вертикальным
центрированием ячеек — все проверки автоматические.

Построчный замер центра формулы по PDF ненадёжен для многострочных записей:
номер выравнивается по одной из строк `cases`, и «центр строки» не равен
центру формулы — центрирование высоких формул проверяй визуально, не только
скриптом.

Визуальная приёмка: проверь по одному представителю каждой формы — высокую
(`cases` или дробь), широкую, обычную; эталон: номер вертикально по центру
высокой формулы, широкая формула без наезда на номер и поля, номер на базовой
линии обычной формулы.
