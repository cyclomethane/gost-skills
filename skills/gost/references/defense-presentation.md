# SKILL: презентация и доклад для защиты ВКР / научной работы

Версия SKILL: 2026-09-16

## 1. Статус документа

Отдельного универсального национального ГОСТ, который задаёт структуру и дизайн презентации ВКР для всех российских вузов, нет. Требования к презентации и докладу устанавливаются образовательной организацией, программой ГИА, кафедрой и конкретным направлением подготовки.

Этот SKILL объединяет проверяемые требования и устойчивые практики из официальных университетских материалов. Он используется как fallback, когда локальная методичка оставляет часть параметров открытыми.

## 2. Приоритет требований

1. Программа ГИА конкретной образовательной программы.
2. Положение о ВКР/защите вуза.
3. Методические указания кафедры.
4. Утверждённый шаблон презентации.
5. Настоящий SKILL.

Число слайдов, длительность доклада, шаблон и обязательные блоки всегда считать LOCAL-параметрами.

## 3. Проверенные университетские ориентиры

Официальные источники показывают различающиеся локальные нормы:
- НИУ ВШЭ в одной из программ устанавливает 7–8 слайдов и требует отражать цель, задачи, объект/предмет, методы/модели, результаты и выводы;
- отдельные программы НИУ ВШЭ задают 6–10 минут для презентации концепции и запрещают чтение текста выступления;
- МГУ в ряде подразделений выделяет актуальность, объект, предмет, цель, задачи и новизну как обязательные элементы презентации;
- методические материалы, размещённые на домене МГТУ им. Н. Э. Баумана, содержат пример локального требования 12–15 слайдов, нумерацию, минимальный кегль 15 pt, светлый фон и обязательные единицы измерения для количественных данных;
- СПбПУ прямо указывает, что требования к презентации задаются конкретной образовательной программой.

Следствие для агента: локальная норма определяет параметры; универсальный шаблон задаёт только логику доказательного рассказа.

## 4. Цель защиты

Презентация должна позволить комиссии быстро проверить:
- какую проблему решает работа;
- как сформулирована цель;
- что сделал автор;
- какими методами;
- какие получены результаты;
- чем они подтверждены;
- какова новизна/практическая значимость;
- где проходят границы применимости;
- как результаты связаны с выводами ВКР.

## 5. Базовая структура исследовательской защиты

При отсутствии жёсткого локального шаблона использовать такую последовательность:

1. Титульный слайд.
2. Проблема и актуальность.
3. Объект, предмет, цель и задачи.
4. Научная новизна / ключевая идея.
5. Метод / математическая модель / алгоритм.
6. Наборы данных или экспериментальный протокол.
7. Ключевой результат №1.
8. Ключевой результат №2.
9. Сравнение с методами сравнения / исходным состоянием.
10. Практическая значимость / программная реализация.
11. Ограничения и границы применимости.
12. Итоговые выводы / положения, подтверждённые экспериментом.

Количество слайдов адаптировать к регламенту. При 7–8 слайдах объединять близкие блоки. При 12–15 слайдах разделять методы и результаты.

## 6. Структура технической/программной ВКР

Рекомендуемая доказательная линия:
1. задача;
2. требования;
3. исходное состояние/проблема;
4. архитектура решения;
5. алгоритм;
6. реализация;
7. тестовый протокол;
8. результаты;
9. сравнение;
10. ограничения;
11. эффект внедрения/применения;
12. выводы.

Код на слайде используется только как краткий фрагмент, необходимый для объяснения алгоритмического решения. Основное доказательство строится через схему, формулу, эксперимент и результат.

## 7. Структура презентации диссертационного типа

Для научной работы высокого уровня:
1. актуальность и проблема;
2. цель;
3. задачи;
4. объект и предмет;
5. научная новизна;
6. положения/результаты, выносимые на защиту;
7. математические модели;
8. численные методы;
9. программный комплекс;
10. протокол вычислительного эксперимента;
11. основные результаты по каждому положению;
12. сравнения;
13. практическая значимость;
14. ограничения;
15. публикации/апробация при необходимости;
16. итоговые выводы.

## 8. Титульный слайд

Минимальный состав, если локальный шаблон не задаёт больше:
- название организации/подразделения при необходимости;
- тема работы;
- ФИО автора;
- программа/группа при требовании;
- ФИО и статус руководителя;
- город;
- год.

Тема должна дословно совпадать с утверждённой формулировкой.

## 9. Актуальность

Актуальность показывается через конкретный дефицит:
- нерешённая научная задача;
- ограничение существующих методов;
- практическая потребность;
- измеримый дефект;
- противоречие между требованиями и существующим состоянием.

Избегать общих формул типа «тема является актуальной в современном мире».

## 10. Цель и задачи

Цель — один конечный научный/инженерный результат. Задачи — этапы, которые действительно выполнены и имеют результат в работе.

На финальном слайде выводы должны зеркально отвечать этим задачам.

## 11. Научная новизна

Формулировать объект новизны явно:
- новая модель;
- новый численный метод;
- новый критерий;
- новая процедура;
- новый алгоритм;
- новая программная реализация как комплекс программ;
- новый подтверждённый экспериментальный эффект.

Каждый пункт новизны должен иметь слайд с доказательной опорой.

## 12. Метод

Показывать метод как короткую цепочку:
`Вход → преобразование → критерий/алгоритм → выход → проверка`.

Для сложного алгоритма использовать схему, псевдокод или формулу. Большие листинги кода переносятся в резервные слайды.

## 13. Экспериментальный протокол

Комиссия должна видеть:
- данные;
- разбиение;
- методы сравнения;
- параметры;
- метрики;
- число повторов/seeds при наличии;
- вычислительную среду, когда она влияет на вывод;
- критерий успеха.

## 14. Результаты

Каждый основной слайд результатов строится по формуле:
**утверждение в заголовке → график/таблица/схема → одно короткое пояснение**.

Заголовок должен сообщать результат, например: `Огрубление до последнего допустимого состояния уменьшает размер представления в 4,1 раза`.

## 15. Графики

График должен иметь:
- понятные оси;
- единицы;
- легенду при необходимости;
- достаточный размер подписей;
- визуальное выделение сравниваемого результата;
- подпись источника данных при внешних данных.

В презентации предпочтителен один главный график на слайд.

## 16. Таблицы

Таблицы подходят для небольшого числа сопоставимых величин. Большие экспериментальные таблицы переводить в heatmap, график или сокращённую таблицу с ключевыми строками. Полная таблица остаётся в ВКР или backup-слайде.

## 17. Формулы

На слайде оставлять только формулы, необходимые для понимания метода или вывода. После формулы дать расшифровку символов в сокращённой форме. Мелкая формула из десятков элементов снижает проверяемость презентации.

## 18. Текст на слайде

Текст должен поддерживать устный доклад. Использовать:
- короткие тезисы;
- существительные и глаголы действия;
- числа;
- выводы;
- подписи к визуализациям.

Длинные абзацы переносить в текст выступления или работу.

## 19. Размер шрифта

При наличии локального минимума применять его. Универсальный fallback для аудитории:
- заголовок обычно 28–36 pt и выше;
- основной текст обычно 20–28 pt;
- подписи графиков обычно 18 pt и выше.

Это редакционные рекомендации, а не ГОСТ. Если слайд требует меньшего кегля, его содержимое следует сократить или вынести в backup.

## 20. Контраст и фон

Высокий контраст обязателен для читаемости. Локальные методички часто рекомендуют тёмный текст на светлом фоне. Допустим и обратный вариант при хорошем проекторе и стабильном шаблоне.

## 21. Цвет

Цвет используется функционально:
- один цвет для основного метода;
- один для метода сравнения;
- один для предупреждений/ограничений.

Не кодировать классы только оттенками, трудными для различения. Палитра должна быть устойчивой к проектору и нарушениям цветового зрения.

## 22. Нумерация слайдов

Если локальная методичка требует нумерацию, титульный слайд обычно остаётся без видимого номера, остальные нумеруются. При отсутствии требования нумерация полезна для вопросов комиссии: `вернитесь к слайду 8`.

## 23. Единицы измерения

Любые количественные данные должны иметь единицы там, где величина имеет размерность. Применять ГОСТ 8.417-2024.

## 24. Ссылки и источники на слайдах

Для внешних данных, изображений и заимствованных графиков указывать краткий источник на слайде и полную запись в работе/backup. Для собственных результатов источник не требуется, но название набора данных и протокол должны быть понятны.

## 25. Доклад

Доклад строится синхронно со слайдами. Рекомендуемый принцип времени:
- 10–15 % — проблема и цель;
- 20–30 % — метод;
- 45–55 % — результаты;
- 10–15 % — выводы.

Конкретный тайминг определяется регламентом защиты.

## 26. Чтение текста

Официальные университетские правила в ряде программ прямо требуют свободного доклада и ограничивают чтение текста со слайдов/заметок. Подготовить устный сценарий и репетировать его по ключевым тезисам.

## 27. Ответы на вопросы

Создать резервные слайды для ожидаемых вопросов:
- подробные параметры;
- дополнительные наборы данных;
- полные таблицы;
- ablation;
- ограничения;
- архитектура программы;
- примеры ошибок;
- формальные доказательства;
- список публикаций.

Backup-слайды располагаются после финального слайда и не входят в основной тайминг.

## 28. Финальный слайд

Финальный слайд должен оставаться на экране во время вопросов и содержать основные результаты/положения. Слайд только со словами «Спасибо за внимание» теряет полезную площадь.

## 29. Техническая готовность

Перед защитой подготовить:
- PPTX;
- PDF-копию;
- локальную копию без интернет-зависимостей;
- шрифты/видео встроенными или заменёнными безопасными форматами;
- запасную флешку при очной защите;
- резервный способ открытия файла;
- проверенную версию на компьютере аудитории при наличии доступа.

## 30. Видео и анимации

Видео включать только при прямой доказательной ценности. Проверить локальный регламент времени. Анимации использовать для последовательного раскрытия сложной схемы, избегая декоративных эффектов.

## 31. Онлайн-защита

Для дистанционной защиты дополнительно проверить:
- разрешение экрана;
- доступ к демонстрации окна;
- стабильность шрифтов;
- читаемость при 720p/1080p;
- микрофон;
- камеру;
- резервный PDF;
- загрузку презентации в LMS в установленный срок.

## 32. Связь презентации с ВКР

Каждое существенное утверждение презентации должно иметь основание в ВКР. Новые экспериментальные результаты, появившиеся только на слайдах, следует включить в текст работы до финальной сдачи либо явно представить как дополнительную демонстрацию при разрешении регламента.

## 33. Чек-лист содержания

- [ ] Тема совпадает с приказом/утверждением.
- [ ] Актуальность конкретна.
- [ ] Цель одна и проверяема.
- [ ] Задачи выполнены.
- [ ] Объект/предмет присутствуют, если требуются.
- [ ] Новизна сформулирована.
- [ ] Метод показан.
- [ ] Эксперимент воспроизводим по ключевым параметрам.
- [ ] Есть методы сравнения.
- [ ] Главные результаты количественно подтверждены.
- [ ] Ограничения указаны.
- [ ] Выводы отвечают задачам.

## 34. Чек-лист оформления

- [ ] Локальный шаблон применён.
- [ ] Число слайдов соответствует регламенту.
- [ ] Слайды пронумерованы, если это требуется.
- [ ] Шрифт читается с последнего ряда.
- [ ] На слайдах нет длинных абзацев.
- [ ] У графиков есть оси и единицы.
- [ ] Таблицы читаемы.
- [ ] Цветовая схема единообразна.
- [ ] Источники внешних материалов указаны.
- [ ] PDF-версия совпадает с PPTX.

## 35. Чек-лист защиты

- [ ] Доклад укладывается в регламент при трёх последовательных репетициях.
- [ ] Доклад произносится свободно.
- [ ] Переходы между слайдами отрепетированы.
- [ ] Ответы на 10–20 ожидаемых вопросов подготовлены.
- [ ] Backup-слайды готовы.
- [ ] Демонстрация проверена на целевом компьютере/проекторе.
- [ ] Файл загружен в LMS в срок.
