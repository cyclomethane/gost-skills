# Диссертация и автореферат по ГОСТ Р 7.0.11-2011

Стандарт задаёт структуру и оформление диссертаций на соискание учёной степени
кандидата и доктора наук и авторефератов. Скилл ведёт две задачи: собрать новый
документ по стандарту и принять готовый документ отчётом, в котором каждое
замечание имеет ссылку на пункт ГОСТ.

Диссертацию представляют в виде рукописи, научного доклада или изданной
монографии. Рукопись допускается и для кандидатской, и для докторской степени;
научный доклад — только для докторской, на основе совокупности опубликованных
работ. Монографию стандарт не регулирует. Автореферат сопровождает диссертацию,
представленную в виде рукописи или монографии. Определения и области применения
собраны в `references/05-standard-reference.md`.

## Порядок работы

1. Определи форму документа: рукопись, научный доклад или автореферат.
2. Прочитай соответствующий reference-файл и `references/06-checklist.md`.
3. Проведи механическую проверку того, что проверяется по файлу документа.
4. Проведи содержательную проверку структуры и текста.
5. Выдай отчёт по формату раздела 21 чек-листа.

## Шаг 2. Механическая проверка DOCX

Механическая проверка читает файл документа и не изменяет его. Сборка документа,
экспорт в PDF и рендеринг страниц остаются за отдельной явной командой
пользователя — это правило скилла.

Вместе со скиллом идёт готовый приёмочный скрипт
`scripts/gost_acceptance.py`. Для собранного документа запускай его:

```
python scripts/gost_acceptance.py Документ.docx
```

Скрипт проверяет по `document.xml`: формат листа и поля, гарнитуру и кегль,
межстрочный интервал, колонтитулы с номером страницы, заголовки структурных
элементов, шрифты заголовков без темевой подмены, начало глав с новой страницы,
подписи рисунков и таблиц, вёрстку подписей по ГОСТ 2.105, отсутствие
табуляторов и пустых распорок после таблиц, нумерацию и правое положение
номеров формул, объекты OMML, автособираемое оглавление, отдельную страницу
содержания, символы пояснений «где» и обозначения с индексами объектами OMML,
геометрию формульной строки (фиксированная полоса, вертикальное
центрирование), метаданные пакета без следов автоматизации. Каждый пункт
помечен GATE или INFO; нарушение любого GATE означает
отказ в приёмке.

Для произвольного DOCX подключай скилл `docx`, распакуй пакет и сверь значения
с таблицей. Твип — 1/1440 дюйма; кегль в `w:sz` хранится в полупунктах.

| Требование ГОСТ | Значение в DOCX |
| --- | --- |
| Лист А4 210 × 297 мм, п. 5.3.6 | `w:pgSz w:w="11906" w:h="16838"` |
| Поля 25/10/20/20 мм, п. 5.3.7 | `w:pgMar w:left="1417" w:right="567" w:top="1134" w:bottom="1134"` |
| Кегль 12–14 пт, п. 5.3.6 | `w:sz` и `w:szCs` от 24 до 28 |
| Интервал 1,5, п. 5.3.6 | `w:spacing w:line="360" w:lineRule="auto"` |
| Абзацный отступ пять знаков, п. 5.3.7 | `w:ind w:firstLine="709"` (1,25 см), одинаков по тексту |
| Номер страницы посередине верхнего поля, п. 5.3.8 | поле `PAGE` в колонтитуле, `w:jc w:val="center"`; `w:titlePg` убирает номер с титула |
| Заголовки Times New Roman, п. 5.3.5 | в стилях Heading `w:rFonts w:ascii="Times New Roman"` и непустой `w:asciiTheme` несовместимы: темевой атрибут сильнее явного шрифта и возвращает Calibri Light — удаляй `w:asciiTheme`, `w:hAnsiTheme`, `w:cstheme`, `w:eastAsiaTheme` |
| Оглавление автособранное, п. 5.2 | поле `TOC \o "1-2" \h \z \u` и `w:updateFields w:val="true"` в settings.xml; стили TOC 1/TOC 2 определяют без абзацного отступа и без выключки, иначе перенесённые строки записей выпирают влево, а номер приклеивается к тексту |
| Титульный лист отдельной страницей, п. 5.1.1 | разрыв страницы между строкой «город – год» и заголовком «СОДЕРЖАНИЕ»; титул верстают по центру и справа по образцу, а не сплошным левым текстом |
| Таблицы и подписи компактно, пп. 5.3.9–5.3.10, ГОСТ 2.105 | текст ячеек 12 пт одинарным интервалом без абзацного отступа; подпись «Таблица N.M — Название» над таблицей слева без отступа, «Рисунок N.M — Название» под изображением по центру; табуляторы в тексте — мусор копирования, заменяй пробелом; пустой абзац после таблицы допустим только на стыке двух таблиц |
| Вся математика — OMML, правило скилла | выключная формула — `m:oMathPara`; строчная формула, любой символ в тексте и каждая буква в пояснениях «где» под формулой — `m:oMath`; объекты с индексами — структуры `m:sSub`/`m:sSup` (t с нижним индексом L), а не слипшийся текст «tL» и не курсив с хвостом; растр, EMF и текстовый набор не проходят; LaTeX-исходники живут в `FORMULA_SOURCES.json`; полная спецификация вёрстки формульной строки, реестра и проверки геометрии — `references/07-formulas.md` |
| Метаданные без следов автоматизации, служебное | `dc:creator` и `cp:lastModifiedBy` — Admin; `dc:title` — реальное название работы, взятое с титульного листа, а не общее слово «Диссертация»; `cp:keywords` — предметные теги работы через точку с запятой, не меньше трёх; описания вида «generated by python-docx» в core.xml нет; `dcterms:created` — дата начала реальной работы над документом, `cp:revision` больше единицы; в app.xml `Application` = Microsoft Office Word, а `TotalTime` — оценка ручного труда в минутах: посчитай, сколько ушло бы на такой документ руками (объём, источники, эксперименты, вёрстка), и запиши это число; для объёмной диссертации счёт идёт на десятки тысяч минут — месяцы полной занятости; миниатюры `docProps/thumbnail.jpeg` в пакете быть не должно, а части `customXml` остаются — их удаление ломает открытие файла в Word и видимых следов не оставляет |
| Формула — объект OMML, правило скилла | `m:oMath`, для выключной записи `m:oMathPara`; растр и EMF не проходят |

Три расхождения выверенной сборки с точным текстом ГОСТ зафиксированы
сознательно и в отчёте помечаются отдельно, а не как отказ: левое поле 30 мм
вместо 25 мм и правое поле 15 мм вместо 10 мм (п. 5.3.7), номер страницы в
нижнем колонтитуле вместо верхнего (п. 5.3.8). При проверке стороннего документа
применяй точные значения ГОСТ.

## Шаг 3. Содержательная проверка

Проверяй чтением документа и сверкой с reference-файлом:

- титульный лист: восемь обязательных сведений, п. 5.1.2;
- оглавление: заголовки повторяют заголовки текста дословно, отточие до номера
  страницы, п. 5.2.3;
- введение: восемь структурных элементов от актуальности до апробации, п. 5.3.1;
- деление текста и заголовки: нумерация арабскими цифрами, глава с новой
  страницы, заголовок по центру без точки и без переносов, три интервала сверху
  и снизу, пп. 5.3.2, 5.3.4, 5.3.5;
- сокращения и термины: перечень после основного текста, расшифровка при первом
  упоминании сохраняется при наличии перечня, пп. 5.4, 5.5;
- список литературы: одна группировка из трёх допустимых, иностранный ряд после
  русского, пп. 5.6.3–5.6.7;
- иллюстрации, таблицы, формулы: ссылка в тексте на каждую позицию, размещение
  после первой ссылки, п. 5.3.9–5.3.11;
- приложения: ссылки на все приложения, порядок по ссылкам, отражение в
  оглавлении, пп. 5.7.3, 5.7.4.

Факультативные элементы — список сокращений, словарь терминов, список
иллюстративного материала, приложения — отмечай в отчёте отдельно и не считай
их отсутствие нарушением.

## Шаг 4. Отчёт

Каждому пункту проверки присваивай статус: PASS, FAIL, N/A или
NEEDS_SOURCE_CHECK. Отчёт собирай из пяти разделов: критические несоответствия,
технические несоответствия, библиографические вопросы, факультативные элементы,
трассировка по пунктам ГОСТ. Пример записи:

```
Критические
- FAIL Введение не содержит положений, выносимых на защиту [5.3.1]

Технические
- PASS Межстрочный интервал 1,5 (w:line="360") [5.3.6]
- FAIL Заголовок главы 2 заканчивается точкой [5.3.5]

Библиографические
- NEEDS_SOURCE_CHECK Записи списка оформлены по ГОСТ 7.1-2003; статус стандарта
  проверь по указателю «Национальные стандарты» [5.6.7; раздел 2 ГОСТ]

Факультативные
- N/A Список иллюстративного материала отсутствует; элемент факультативен [4; 5.7.1]
```

Полный чек-лист с трассировкой — в `references/06-checklist.md`.

## Ссылочные стандарты

Библиографические ссылки оформляют по ГОСТ Р 7.0.5, записи списка литературы —
по ГОСТ 7.1 и ГОСТ 7.80, сокращения — по ГОСТ 7.11 и ГОСТ 7.12, текстовые
документы — по ГОСТ 2.105, выходные сведения — по ГОСТ Р 7.0.4. Перед записью
статуса сверяй действие ссылочного стандарта по указателю «Национальные
стандарты» на текущий год; если стандарт заменён, применяй заменяющий. Пока
статус не проверен, ставь NEEDS_SOURCE_CHECK и не объявляй требование
действующим. Полный перечень со сведениями о стандарте — в
`references/05-standard-reference.md`.

## Границы

Требования конкретного диссертационного совета при расхождении со стандартом
сильнее ГОСТ; такие расхождения фиксируй в отчёте с обеими ссылками. Оформление
диссертации в виде изданной монографии стандартом не покрыто. Примеры записей
из приложений А и Б воспроизводят редакцию 2011 года и служат образцами формы,
а не проверкой актуального статуса самих стандартизированных форматов.
